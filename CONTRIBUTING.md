# Разработка и подготовка изменений

## Окружение

Используйте Python из `.python-version`, uv и существующий `uv.lock`.
Для тестов достаточно `uv sync --locked`. Для соответствующих сценариев добавляйте
`--extra audio`, `training`, `tts-windows`, `cuda`, `notebook`, `whisperx` или `diarization`.
Не создавайте параллельные списки `requirements*.txt`.

Изменение зависимостей: отредактируйте `pyproject.toml`, выполните `uv lock` и
включите оба файла в один коммит. Не заменяйте ограничения PyAV/CTranslate2/CUDA
без проверки реального декодирования и GPU runtime.

## Проверки

```powershell
uv lock --check
uv run --locked pytest -q
git diff --check
```

Тесты используют искусственные записи и не требуют работающих Telegram/Redis/Ollama.
С дополнением `audio` дополнительно проверяется настоящее декодирование WAV.
Dockerfile выполняет Linux-проверку импорта и декодирования при сборке.

Для изменения GPU-конфигурации проверьте `python -m app.gpu_check` в GPU-worker,
затем обработайте новую запись. Для изменения моделей сравнивайте validation/test,
сохраняя исходное разбиение; test не должен участвовать в выборе кандидата.

## Что включать в Git

Исходники, тесты, документацию, шаблоны `.env`, lock-файл и конфигурации Compose.
Данные, веса, рабочие заметки, отчёты с именами файлов, аудио/видео и токены остаются
локально. Не добавляйте исключённые файлы через `git add -f`.

Публикуемые результаты должны быть агрегатами без исходных текстов и пользовательских
путей. Пример: `docs/results/baseline.json`. Указывайте версию данных, метод разбиения,
baseline, метрики обоих классов и ограничения. Выводы учебных ноутбуков перед коммитом
очищайте; реальные коммерческие данные не используйте как демонстрационные примеры.

## Подготовить коммит

```powershell
git status --short
git add .
git diff --cached --stat
git diff --cached
git commit -m "docs: prepare VoiceFlow MVP for publication"
git push
```

Перед `commit` проверьте состав изменений. Команды не создают новый репозиторий,
remote или ветку; `push` предполагает уже настроенный upstream.
Не добавляйте в публичные issues секреты и рабочие журналы без обезличивания.
