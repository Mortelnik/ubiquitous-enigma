# Техническое состояние MVP — 17 ноября 2026

Снимок проверок репозитория для публикации. Рабочие сценарии веба и Telegram
подтверждены пользователем. Это проверка конфигурации и поведения приложения,
а не полный аудит уязвимостей зависимостей и не оценка качества всех моделей.

## Проверено

| Область | Результат |
|---|---|
| Зависимости | Единые `pyproject.toml` и `uv.lock`; установка через uv |
| Python | По умолчанию 3.12; диапазон проекта 3.12–3.13 |
| Тесты | 86 тестов с дополнением `audio`; внешние сервисы не требуются |
| Аудиосреда | Настоящее декодирование WAV через Faster-Whisper/PyAV без модели |
| Compose | Базовый CPU, Windows Obsidian и GPU + storage + bot проходят валидацию |
| Сервисы | API, worker, bot запущены; Redis и Ollama проверены как healthy |
| API | `/health` с ключом отвечает `ok`; локальный классификатор готов |
| GPU runtime | Worker обнаружил одно CUDA-устройство, загрузил cuBLAS 12/cuDNN 8, поддерживает float16 |
| Веб / Telegram | Пользователь подтвердил работу обоих каналов |
| Базовая модель | Метрики JSON совпадают с метаданными joblib, отпечатки текущих выборок проверены |
| Notebook | Сохранённых выводов нет |
| Подготовка к GitHub | Проверены 73 файла-кандидата и доступная Git-история: известные шаблоны токенов и локальные ключи не обнаружены |

GitHub Actions проверяет lock-файл, запускает тесты, валидирует Compose и собирает
CPU-аудиообраз. Сборка проверяет нативный импорт и WAV-декодирование. GPU runtime
проверен на локальном стенде; GitHub runner без GPU его не проверяет.

## Исправления, включённые в MVP

- Раздельные uv-дополнения: API/бот не устанавливают NeMo, PyTorch и ноутбуки.
- PyAV 16.0.1 совместим с вызовом `metadata_errors` в Faster-Whisper 1.2.1.
- Для Linux wheel CTranslate2 4.4 исправляется ошибочный флаг исполняемого стека;
  системная защита не отключается. Проверка выполняется при сборке Docker.
- На Windows ограничен setuptools: CTranslate2 4.4 требует `pkg_resources`.
- Whisper определяет GPU через CTranslate2 независимо от PyTorch.
- GPU override устанавливает CUDA 12/cuDNN 8, включает float16; fallback использует int8.
- Ollama доступна внутри Compose без публикации порта Windows 11434.
- Windows Obsidian подключается одинаково к API и worker через storage override.
- Telegram поддерживает allowlist, отдельный API-ключ, начальные сетевые повторы и прокси.
- Ответы Telegram и веба показывают стиль и метрики; выключенная диаризация не
  выдаётся за измерение одного реального спикера.
- Redis обеспечивает FIFO, квоты и идемпотентность; worker наблюдает отдельный процесс
  задачи, ограничивает время и подтверждает отмену после его остановки.
- В Git исключены конфигурация с секретами, медиа, данные, веса и рабочие результаты.

## Опубликованные результаты обучения

Базовый эксперимент `real_only`, 59 485 train / 1 826 validation / 1 829 test.
Test accuracy — 94,86%, balanced accuracy — 88,70%, macro-F1 — 0,9094.
У постоянного baseline test macro-F1 — 0,4493. Из-за дисбаланса отдельно приведены
метрики обоих классов: recall разговорного — 78,93%, официального — 98,46%.

Источник чисел — локальная сохранённая модель и JSON обучения, а не старый ноутбук.
Публикуется только агрегированный снимок `docs/results/baseline.json` с версией
источника, SHA-256 модели и отпечатками выборок. Корпус, веса и пользовательские
транскрипты остаются локально. Подробности: `DZ_03/Отчёт.md`.

## Ограничения и оставшаяся оценка

- Доменные метки слабые; нет отдельной опубликованной оценки на вручную размеченных
  голосовых Telegram. Доли строк различаются из-за сохранения целых групп.
- TTS-код и проверки подготовлены, но опубликованного сравнения real-only / real+TTS
  пока нет. Прирост качества не заявляется.
- Полный GPU-инференс не измерялся агентом по контрольной записи; подтверждены
  доступность GPU/runtime и работоспособность приложения пользователем.
- NeMo и WhisperX не проходили отдельную сквозную проверку на этом стенде.
- Бот не восстанавливает фоновые уведомления после перезапуска: результаты остаются
  в Obsidian и серверном реестре задач.
- Worker запускается от root в контейнере. Внешняя публикация сервиса и изоляция
  недоверенных пользователей не входят в подтверждённый локальный сценарий.
- Исходники, кэш и отчёты содержат рабочую информацию и не предназначены для GitHub.
