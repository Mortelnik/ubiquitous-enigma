# Запуск варианта 1 в Windows

Основная модель: TF-IDF + LogisticRegression. Классы: **0 — разговорный,
1 — официальный**. Синтетическое происхождение не является целевой меткой.

Все команды ниже выполняются в PowerShell на компьютере, из корня репозитория,
а не внутри контейнера. Нужен установленный uv. Загрузка, синтез и обучение
выполняются пользователем; готовых весов в Git нет. Обезличенные результаты
базового обучения опубликованы в `docs/results/baseline.json`.

## 1. Данные и базовая модель

```powershell
# Откройте PowerShell в корне клонированного репозитория.
uv sync --locked --extra training

# Публичные текстовые аннотации; аудиоархивы не скачиваются:
uv run --locked --extra training python -m scripts.download_balalaika

# Подготовка, дедупликация и разбиение без пересечения групп:
uv run --locked --extra training python -m DZ_03.model_pre

# Обучение основной модели, общая предобработка с приложением:
uv run --locked --extra training python -m DZ_03.train_classifier
```

Результаты:

- `data/raw/download_manifest.json` — версия и состав источника;
- `data/processed/dataset_stats.json` — фактические размеры и классы выборок;
- `models/style_classifier.joblib` — модель, готовая для приложения;
- `models/style_classifier.metrics.json` — validation/test: accuracy, balanced
  accuracy, macro-F1, метрики классов, confusion matrix и постоянный baseline.

Доли групп приблизительно 70/15/15; доли строк могут сильно отличаться из-за размера
целых групп. Доменные метки слабые; классы отдельных
реплик могут отличаться от домена. Подготовка останавливается при недостатке
независимых групп или противоречиях. Не убирайте эти проверки ради запуска.

Уже на этом этапе можно перейти к шагу 4 и проверить бота с базовой моделью.

## 2. Локальный TTS и повторная транскрибация

В комплекте есть адаптер для русского голоса, установленного в Windows и
доступного через `SAPI`. Посмотрите список доступных голосов:

```powershell
uv run --locked --extra tts-windows python -m scripts.tts_windows --list-voices
# Проверить одну фразу; временный WAV удаляется после проверки:
uv run --locked --extra tts-windows python -m scripts.tts_windows --check
```

Если русского голоса нет, установите русский речевой голос в настройках языка
Windows и повторите проверку. Адаптер использует только голоса, видимые
`SAPI`, и останавливается, если русского голоса нет. Также можно
использовать другой локальный TTS: подготовьте JSON-массив его аргументов,
как описано ниже. Облачный TTS в этом сценарии не используется.

Другой локальный движок подключается JSON-массивом аргументов. Он получает текст
в UTF-8 через stdin и должен записать PCM WAV по пути `{output}`. Плейсхолдер
`{python}` заменяется на Python текущего окружения uv. Пример структуры:

```json
["{python}", "scripts/my_local_tts.py", "--output", "{output}"]
```

`my_local_tts.py` здесь обозначает ваш адаптер, а не файл из репозитория.
Готовый Windows-адаптер подключён в `scripts/tts-command.windows.example.json`.

```powershell
uv run --locked --extra training --extra audio --extra tts-windows python -m scripts.tts_synth --phrases data/processed/train.parquet --out data/tts/run1 --command-file scripts/tts-command.windows.example.json --max-per-class 200 --transcribe --whisper-model base --language ru
```

Берётся до 200 фраз каждого класса, только из train, с seed=42. Это начальный
объём эксперимента, а не требуемый размер датасета. Для полного train используйте
`--max-per-class 0`. Для другого голоса или повторного запуска укажите новый
каталог `--out`, например `data/tts/run2`; существующие WAV не перезаписываются.

Синтез работает локально. При первом обращении Faster-Whisper может скачать
веса ASR; для работы без интернета заранее подготовьте модель и укажите её
локальный путь через `--whisper-model`. Используйте ту же модель и язык, что
указаны для распознавания в приложении (`WHISPER_MODEL`, `LANGUAGE`). Здесь
`base`/`ru` соответствуют исходному Docker-шаблону.

Результат: `data/tts/run1/manifest.csv` с исходным текстом, меткой стиля,
исходной группой, `is_synthetic`, путём WAV, `asr_text` и настройками ASR.
Адаптер Windows также записывает `tts_engine` и `tts_voice`; команда и число
примеров сохраняются рядом в `synthesis.json`.
Прослушайте несколько WAV каждого класса и проверьте транскрипты перед обучением.
Если Whisper возвращает пустую русскую речь, синтез останавливается с ошибкой.

## 3. Сравнение без TTS и с TTS

```powershell
uv run --locked --extra training python -m DZ_03.compare_experiments --synthetic data/tts/run1/manifest.csv
```

Скрипт повторно обучает две модели с одинаковыми настройками на тех же split-файлах.
Вторая получает дополнительно ASR-транскрипты TTS. Validation/test остаются
реальными и неизменными. Отпечатки выборок записываются в артефакты и проверяются.
TTS-фразы вне train, неверные метки/группы и пересечения ASR с validation/test
приводят к ошибке, а не к молчаливому удалению примеров.

Артефакты:

- `models/experiments/real_only.joblib` и `real_plus_tts.joblib`;
- метрики каждой модели в соседних `.metrics.json`;
- `models/experiments/comparison.json` и `comparison.md` — таблица сравнения,
  количество реальных/синтетических примеров, отпечатки и настройки.

Кандидат выбирается по **validation macro-F1**, при равенстве — модель без TTS.
Test используется только для финальной оценки. Постоянный baseline одинаков
для обоих экспериментов и обучается на исходном реальном train.
TTS может как улучшить, так и ухудшить качество — это нужно отразить в отчёте.

По умолчанию сравнение сохраняет базовую модель приложения. Чтобы сразу
установить кандидата, выбранного по validation, добавьте `--deploy`:

```powershell
uv run --locked --extra training python -m DZ_03.compare_experiments --synthetic data/tts/run1/manifest.csv --deploy models/style_classifier.joblib
```

Команда заново выполняет сравнение и копирует выбранный артефакт вместе с его
метриками. Test не используется для выбора даже при таком запуске.

## 4. Контейнеры и проверка

В `.env.docker` заполните `TELEGRAM_BOT_TOKEN` и `BOT_ALLOWED_USER_IDS`.
Для обычного CPU-сценария оставьте `UV_EXTRAS=audio`, `ENABLE_DIARIZATION=false`.
Классификатор должен находиться в `models/style_classifier.joblib`.

Для первого запуска подготовьте `.env.docker` и API-ключи по инструкции в README.
Если нужны GPU, папка Windows Obsidian и ответы Telegram, используйте команды
из [WINDOWS_RESULTS.md](../WINDOWS_RESULTS.md), включая все override-файлы при
следующих обновлениях. Команда ниже — базовый CPU-вариант с внутренним томом Obsidian.

```powershell
docker compose --env-file .env.docker --profile bot up -d --build --force-recreate
docker compose --env-file .env.docker --profile bot logs -f --tail 100 bot worker
```

Веб-интерфейс: `http://127.0.0.1:8000`, ключ — значение `VOICEFLOW_API_TOKEN`
из `.env.docker`. Должно отображаться «Классификатор: готов». Отправьте по одному
голосовому каждого стиля: после транскрибации должен определиться класс,
выбраться `prompt_2` для разговорного либо `prompt_1` для официального и
сохраниться результат в Obsidian. Модель Ollama нужно предварительно загрузить.

Модели подключаются из локальной папки `models` только для чтения. После
последующего обновления весов достаточно обновить страницу; пересборка образа
нужна при изменении кода или зависимостей.

## 5. Отчёт и независимая оценка

Заполните таблицы `DZ_03/Отчёт.md` фактическими числами из артефактов.
Отдельно проверьте небольшой вручную размеченный набор реальных голосовых,
не использованных в обучении и подборе параметров. Доменные метки Balalaika
не гарантируют точность на Telegram. Технические тесты на искусственных фразах
не являются метриками качества классификатора.
