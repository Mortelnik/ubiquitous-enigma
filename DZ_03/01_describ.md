# 3 семестр: обработка естественного языка

Команда 7: Шелест М.А. · Иванова Ю.С. · Романенко Д.Н. · Ишбулатова С.С. · Буянов Е.Э.

## Кейс: классификация аудиосообщений по стилю речи

Выбран вариант 1: **TF-IDF + LogisticRegression** как основная модель и
эксперимент с TTS-аугментацией. Выход: 0 — разговорный, 1 — официальный.
Признак «реальное/синтетическое» описывает происхождение и не является целевым классом.

Система продолжает локальный проект транскрибации и саммаризации:

1. Telegram-бот или локальная веб-страница принимает аудио.
2. FFmpeg и локальный Faster-Whisper получают транскрипт.
3. Сохранённый классификатор определяет стиль транскрипта.
4. По классу выбирается промпт: 0 → `prompt_2`, 1 → `prompt_1`.
5. Локальная Ollama создаёт саммари, результат сохраняется в Obsidian.

Диаризация необязательна, по умолчанию выключена и требует дополнительных библиотек.
Для строгого требования хранения входных данных только на ПК используется веб-ввод:
исходные сообщения Telegram уже находятся на серверах Telegram.

## Данные

Основной учебный источник — [OpenSTT Balalaika](https://huggingface.co/datasets/lab260/openstt_balalaika).
Загрузчик `scripts/download_balalaika.py` скачивает только пять используемых Parquet-файлов
текстовых аннотаций и фиксирует commit источника. Аудиоархивы для обучения текстового
классификатора не нужны. На странице источника указана лицензия CC BY-NC 4.0.

Слабые доменные метки при отсутствии предоставленных меток:

| Класс | Домены |
|---|---|
| 0 — разговорный | `asr_public_phone_calls_1`, `asr_public_phone_calls_2`, `public_series_1` |
| 1 — официальный | `public_lecture_1`, `public_speech` |

Радио, YouTube, художественные истории и аудиокниги не получают автоматических меток:
домен не гарантирует стиль отдельной реплики. Подкасты не считаются отдельным
подтверждённым разговорным классом. Корпус требует независимой ручной проверки.

Golos и стенограммы Госдумы остаются возможными будущими источниками. В текущий
загрузчик и эксперимент они не входят. Добавлять новые источники нужно до общего
разбиения, сохраняя метки и идентификаторы групп.

## Подготовка и основной классификатор

- Нормализация: русские буквы, нижний регистр, пробелы; от 3 до 300 слов.
- Порог MOS 4.0 и флаг одного диктора учитываются при наличии значений.
  Неизвестные значения этих полей сами по себе не удаляют строку.
- Одинаковые нормализованные тексты дедуплицируются; конфликтующие метки отклоняются.
- Общие тексты и доступные ID записей/дикторов объединяются в группы до разбиения.
- Train/validation/test: примерно 70/15/15 без пересечений групп.
- TF-IDF: слова 1–3-граммы и символы 3–5-граммы, обучение словаря только на train.
- LogisticRegression: `class_weight="balanced"`, `random_state=42`.
- Векторизаторы и классификатор сохраняются одним pipeline в joblib.

CNN, ансамбль и трансформеры не входят в выбранный вариант. Ноутбук использует
тот же код подготовки/обучения, что и командные скрипты.

## Усложнение: TTS

Синтезируются только фразы исходного train обоих классов. Локальный TTS создаёт WAV,
тот же тип ASR получает транскрипты, которые добавляются в train с исходными
метками стиля. Validation/test не дополняются синтезом и не меняются.
В Windows доступен адаптер `scripts/tts_windows.py` для установленного русского
голоса SAPI; другой локальный движок подключается JSON-командой.

Сравниваются две модели с одинаковыми параметрами: реальные транскрипты и реальные
плюс TTS→ASR. Выбор кандидата — по validation macro-F1, при равенстве остаётся
вариант без TTS. Test используется для финальной оценки. Улучшение от TTS не предполагается заранее.

## Проверка результата

Нужно измерить accuracy, balanced accuracy, macro-F1, precision/recall/F1 каждого
класса, confusion matrix и постоянный baseline. Дополнительно нужен вручную
размеченный набор реальных голосовых вне обучения и подбора параметров.

Новые показатели не заявляются до фактического запуска. Результаты оформляются
в `Отчёт.md`. Все команды: [RUNBOOK.md](RUNBOOK.md).
