# Эксплуатация VoiceFlow AI

## Ограничение нагрузки и порядок задач

Все новые задания сначала атомарно резервируются в Redis. Значения по умолчанию:

| Параметр | Значение | Назначение |
|---|---:|---|
| QUEUE_MAX_USER_JOBS | 3 | Всего загрузок, ожидающих и выполняющихся задач пользователя |
| QUEUE_MAX_JOBS | 20 | Вместимость сервиса, включая веб-загрузки |
| QUEUE_ADMISSION_INTERVAL_SEC | 3 | Минимальный интервал приёма задач одного пользователя |
| UPLOAD_TIMEOUT_SEC | 180 | Время от резервирования до завершения загрузки |
| QUEUE_TIMEOUT_SEC | 3600 | Предельное ожидание запуска с момента приёма |
| PROCESS_TIMEOUT_SEC | 900 | Отдельное время выполнения после запуска |
| MAX_AUDIO_DURATION_SEC | 600 | Максимальная длительность аудио по FFprobe |
| FFMPEG_TIMEOUT_SEC | 120 | Ограничение конвертации |
| OLLAMA_TIMEOUT_SEC | 180 | Таймаут обращения к Ollama |
| JOB_HISTORY_SEC | 86400 | Хранение статусов и защита от повторов |
| UPLOAD_RETENTION_HOURS | 24 | Хранение исходников/кэша завершённых задач |

Применяется **общий FIFO по моменту резервирования**, включая Telegram и веб.
Бот принимает обновления последовательно, фиксирует промпт и резервирует место до
скачивания. Фоновые загрузки ограничены `BOT_DOWNLOAD_CONCURRENCY=2`.
Поздняя быстрая загрузка не обгоняет раннюю медленную. Незавершённая загрузка в начале
очереди задерживает остальных до её завершения/отмены/таймаута; это намеренный выбор
строгого порядка вместо обработки по готовности. Распределения round-robin нет.

В очередь Celery передаётся только головное готовое задание. Redis-реестр служит
восстанавливаемым outbox: если публикация или worker не подтвердили запуск за 30 с,
API повторяет отправку того же ID. Атомарное получение владения не позволяет повторной
доставке повторить обработку. Приём завершается ошибкой при недоступности Redis —
неограниченной локальной резервной очереди нет. В Docker включено AOF Redis; при
аварийном выключении всё ещё возможна потеря последней секунды записей AOF.

Каждая тяжёлая задача запускается отдельным процессом под наблюдением worker, в том
числе при `--pool=solo`. При отмене API возвращает `CANCEL_REQUESTED`. Worker завершает
процесс и только затем подтверждает `REVOKED` и освобождает место. Ожидающая задача
отменяется сразу. При достижении времени выполнения процесс также останавливается.
Не следует заменять это вызовом `celery revoke(terminate=True)` для solo.
Остановка локального клиента не гарантирует мгновенное прекращение уже запущенной
генерации на внешнем процессе Ollama; для обращения также действует отдельный таймаут.

Ключ `VOICEFLOW_BOT_API_TOKEN` отделён от ключа веб-интерфейса. Только он разрешает
`POST /jobs/reserve` с Telegram user/chat/message ID. `scripts/docker.ps1 -Action init`
создаёт оба ключа, сохраняя существующие. В Docker они передаются через `.env.docker`.
При ручном запуске скопируйте соответствующий ключ также в окружение бота/API.
Повторная доставка `(chat_id, message_id)` возвращает существующую задачу в пределах
`JOB_HISTORY_SEC`. Для веб-клиентов предусмотрен заголовок `Idempotency-Key`.

Бот использует общую HTTP-сессию и увеличивает интервал опроса с 2 до 15 секунд,
добавляя небольшой случайный сдвиг; при сбоях также увеличивается пауза.
Команды и callback-запросы ограничиваются отдельно. При частых повторах уведомление
об ограничении отправляется не чаще раза в 10 секунд. Ответы Telegram учитывают Retry-After.
Таймаут ожидания очереди отделён от обработки; запрос отмены не выдаётся за её подтверждение.

Перезапуск бота не сбрасывает серверные квоты и не удаляет уже принятые задачи.
Фоновые уведомления бота не восстанавливаются после его перезапуска: результаты остаются
в Obsidian, а статус доступен через `/status/{task_id}` с ключом API. Команда `/queue`
показывает незавершённые задачи пользователя; `/cancel <номер>` запрашивает отмену
с проверкой принадлежности задачи. При перезапуске самого
worker незавершённая задача может завершиться ошибкой по серверному таймауту;
автоматическое повторение её побочных эффектов не выполняется.

Для обновления существующей установки:

```powershell
.\scripts\docker.ps1 -Action init
.\scripts\docker.ps1 -Action rebuild -Bot
```

В режиме GPU добавьте `-Gpu`, для Windows-папки Obsidian — `-LocalVault`. Новые ограничения относятся к заданиям, принятым после
обновления; старые записи только в Celery без нового реестра автоматически не импортируются.


### Ошибки запуска аудио и связи с Telegram

Если worker падает с `TypeError: open() got an unexpected keyword argument
'metadata_errors'`, пересоберите worker из текущего репозитория. В uv закреплён
PyAV 16.0.1, совместимый с Faster-Whisper 1.2.1. Сборка дополнительно проверяет
декодирование WAV без скачивания модели. HF_TOKEN не исправляет эту ошибку.

Если Linux-библиотека CTranslate2 сообщает `cannot enable executable stack`,
пересоберите worker из текущего Dockerfile. Старый wheel CTranslate2 4.4
(сохранён для совместимости необязательного WhisperX) содержит ошибочный ELF-флаг.
Сборка через `patchelf --clear-execstack` снимает требование исполняемого стека
только у библиотек CTranslate2 и проверяет результат. Настройки защиты загрузчика
не отключаются; версии numpy/scikit-learn/joblib и модель классификатора не меняются.
После установки сборка проверяет импорты CTranslate2/Faster-Whisper без скачивания
ASR-моделей. Эта проверка также выполняется при сборке аудиообраза в CI.

`Cannot connect to host api.telegram.org:443` — отдельная проблема соединения с Telegram.
Бот повторяет начальный `getMe` с растущей паузой до 60 секунд; это не восстанавливает
маршрут VPN. Проверьте, что VPN обслуживает трафик Docker Desktop. Если у VPN-клиента
есть локальный HTTP/SOCKS-прокси, укажите его адрес в `.env.docker`, например:

```dotenv
# 7890 — пример; нужен фактический порт вашего VPN-клиента.
TELEGRAM_PROXY_URL=http://host.docker.internal:7890
```

Этот прокси используется только для Telegram; внутренний API остаётся доступен напрямую.
Пустое значение означает прямое подключение. Адрес прокси с паролем не выводится
в сообщениях повторного подключения. Отправка сообщений после неопределённого
сетевого сбоя не повторяется автоматически, чтобы не создавать дубли.

После изменения кода/зависимостей пересоберите сервисы с теми же override-файлами,
с которыми они запущены. Ниже только базовый CPU-вариант:

```powershell
docker compose --env-file .env.docker --profile bot up -d --build --force-recreate
```

После изменения только `.env.docker` пересоздайте затронутые сервисы без сборки.
Обычный Restart не перечитывает окружение. Для GPU и Windows Obsidian сохраняйте
полный набор `-f` из `WINDOWS_RESULTS.md`.
Неудавшееся голосовое отправьте заново; завершённые ошибкой задачи не повторяются сами.
Предупреждение Celery о запуске от root отдельно от ошибки импорта; оно не объясняет
отказ CTranslate2. Смена пользователя контейнера требует отдельной настройки прав
существующих томов и не выполняется этой правкой.
